01What this project is

A direct-booking site for a Berber family guiding operation in the High Atlas. It sells trekking, desert and cultural tours from Marrakech and Agadir, in six languages, without an intermediary taking 25–40% commission.

The commercial premise shapes the architecture. Booking platforms charge operators a quarter to two-fifths of the ticket price; on a €195 trek that is up to €78 that never reaches the guide, the muleteer or the refuge. Every technical decision here — the static generation, the six-locale content model, the aggressive SEO instrumentation — exists to make direct discovery work well enough that the intermediary becomes unnecessary.

The ratio that explains the project

Library code outweighs application code roughly 15:1. That is not bloat — it is the deliberate consequence of storing all content as typed TypeScript rather than in a CMS. Every tour, article and translation is a compile-checked object, so a missing field or a mistyped price fails the build instead of reaching a customer.

The content-as-code decision

There is no CMS. Tours and articles live in TypeScript files with declared interfaces, which buys three properties a database cannot:

  • Compile-time safety. A tour missing itinerary fails tsc, not a page render.
  • Reviewable diffs. A price change is a line in a commit, attributable and revertible.
  • Testable content. Assertions run against the catalogue itself — every price, every meta description, every internal link.

The cost is that content edits require a deploy. For a catalogue that changes weekly rather than hourly, that trade is favourable.

04The six-locale system

English, French, Spanish, German, Italian and Arabic — not machine-translated at request time, but authored per language and merged at build.

How a locale page is assembled

  1. proxy.ts resolves the locale prefix and, where one exists, the localised URL segment.
  2. {entity}-i18n.ts layers the locale record over the English one.
  3. Missing fields fall back to English rather than rendering empty.
  4. dictionaries/{locale}.json supplies UI strings — labels, buttons, headings.

Two merge strategies, deliberately different

EntityStrategyRationale
ToursPer fieldStructural data (price, coordinates) shared; prose translated. A missing field degrades to English, not undefined.
Blog postsPer postAn article is translated wholly or not at all; a half-English post is worse than an English one.

The empty-array trap

The per-field merge overlays any value that is not undefined, null or "". An empty array passes that guard. So itinerary: [] in a locale file type-checks, builds, renders a page — and silently ships a booking page with no itinerary, because the English fallback never fires.

This is now caught by fixed-departure.test.ts, which asserts through the same function the page calls, so it tests the merged result a reader actually sees.

Localised URLs

Some tours carry a localizedSlug, so the French page serves at /fr/tours/trek-sommet-toubkal-4-jours while the English URL 308-redirects to it. That requires three files to agree: the tour data, the forward map in proxy.ts, and the reverse map in lib/locale-switch.ts. Drift between them sends a live, indexed booking page to a 404 — so two test suites exist purely to assert they match.

05Pricing architecture

Prices are stored in USD and displayed in EUR. This single fact is responsible for more historical defects than any other design choice, and for the tests that now guard it.

Storage and conversion

Conversion happens at 0.86693, defined in lib/currency-core.ts with an instruction to review quarterly. Four currencies are offered — EUR (default), USD, GBP, MAD.

The conversion defect this causes

Writing a customer-facing figure directly into price produces the wrong number: price: 889 renders as €771, not €889. Stored values must be solved backwards from the intended display price — 1025 × 0.86693 = 888.6 → €889.

The same trap bit the blog: prose quoting the stored USD figure with a euro sign overstated eight cost articles by ~9% across six languages before blog-prices.test.ts existed.

Two pricing models

ModelMechanismWhy
PrivategroupPricing ladder: per-person rate falls as group growsGuide and vehicle are a fixed cost divided among the party
Fixed departureFlat seat price; fixedDeparture carries dates, seat cap, list priceTrip runs on its published date regardless; what varies is availability

Three helpers keep the ladder honest across every surface: groupPriceTiers(), lowestGroupPrice() and perPersonPrice(). Listing cards once displayed tour.price — the solo rate, the most expensive figure a tour has — advertising €1,800 for a trek a group of five pays €695 for. lowestGroupPrice() exists because of that incident.

Invariants under test

  • A larger party never pays less in total than a smaller one.
  • The per-person price never rises as the group grows.
  • The advertised headline equals the first bookable tier.
  • A fixed departure carries no ladder, and its list price genuinely exceeds its selling price.
  • Every price quoted in prose matches the tour data — in all six languages.

06The regression-test culture

51 suites, 402 assertions. Almost every one exists because a specific defect reached production and nothing in the build caught it.

The convention: write the incident, not the assertion

Each suite opens with a docblock naming what shipped, what it cost, and why nothing else caught it. The distinction matters:

// Bad — restates the assertion /** Checks that blog prices match tour prices. */ // Good — records the incident /** * Tour prices are stored in USD and rendered in EUR. Blog prose that * quotes the stored number with a euro sign overstates the price by * ~9% — the article says €245 while the booking page says €225. * * That shipped across all eight cost posts in six languages before * this test existed. Nothing else catches it: the number is valid * TypeScript, the page builds, and only a reader comparing the two * notices. */

The second form tells the next reader why the check is shaped as it is, so they can distinguish a real failure from a false positive instead of deleting the test.

Three supporting rules

  • Assert catalogue-wide, not on today's change. Defects recur on pages nobody is editing. The FAQ-parity check has caught three separate incidents; the orphan check caught four commercial pages sitting at positions 48–73.
  • Failure messages name the fix. They list offending items and state the remedy, because they are read by someone who did not write the test.
  • Encode the rule, not the data. expect(TOURS.length).toBe(46) fails on the next tour added and teaches nothing.

What the suites cover

Pricing: price-ladder, group-pricing, price-floor, blog-prices, currency, min-people, deposit-link, tipping-consistency

Localisation: hreflang, locale-switch, localized-slugs, localized-tour-slugs, faq-locale-parity, seo-i18n, shared-tours-parity, hero-image-locale-sync

A known blind spot, documented

Vitest never imports page components. A JSX syntax error can therefore break tsc while all 402 tests pass. The verification sequence exists for exactly this reason and runs typecheck, tests, build and the hreflang audit in order — next build exiting 0 does not prove a page rendered, so the artefact is checked on disk.

Two refusals worth recording

Event offers. Adding our tour price to a festival's Event.offers would tell Google that €95 buys admission to the Gnaoua Festival. It does not — the festival is free. Recommended field left empty rather than filled dishonestly.

Invented anchors. A struck-through "was" price is only emitted where the higher figure is genuinely charged outside a promotion. The EU Omnibus Directive requires it, and Google treats a fabricated anchor as misleading markup.

Indexing pipeline

A four-step sequence, with the diff as the source of truth:

npx next build # sitemap is generated, never hand-edited node scripts/build-index-urls.mjs # rebuild master list from the BUILT sitemap node scripts/seo/diff-unsubmitted.mjs # current list vs what was actually sent .\scripts\index-batch.ps1 <batch> # submit, quota-tracked

The submitter is guarded by two pre-flight checks, each added after a real loss:

  • Duplicate guard. On 2026-08-16, 200 URLs were re-sent because a queue was rebuilt from the sitemap instead of read from the state file. Google accepts duplicates silently, so nothing failed and nothing surfaced — the cost was a full day of quota buying nothing.
  • Live-URL guard. A batch built the instant a commit was pushed found all URLs returning 404: Vercel had not finished deploying. They went live ~105 seconds later. Submitting in that window spends quota to show Google a 404.

Verification is currently impossible — a Google-side defect

As of 28 August 2026, urlNotifications:publish returns HTTP 200 but with a metadata object containing only the URL; the documented latestUpdate field is absent. urlNotifications/metadata then returns 404 for that URL indefinitely.

Reproduced deliberately: a publish returned 200, and a read three seconds later returned 404 NOT_FOUND. Every URL this project has submitted reads back as 404, including ones observed succeeding. Google's tracker has it at p2, reported across the Node, Python and PHP clients.

Consequence: a 404 from the verifier proves nothing, and re-sending on that basis would repeat the 2026-08-16 waste. Search Console's Page Indexing report is the only real check.

08Content systems

The events date-confidence model

Moroccan festival dates move by three distinct mechanisms, and conflating them puts wrong dates on a booking page. lib/events.ts encodes the distinction in the type system:

ConfidenceMeaningRendering
confirmedOrganiser has published the dateStated flatly; sourceUrl required
estimatedTied to a harvest or season, unannouncedA window, never a precise day
lunarHijri calendar, fixed by moon sightingNever presented as exact

Tests fail if an estimated or lunar event carries a single-day date, or if a confirmed one lacks an organiser URL.

Why aggregators are not acceptable sources

Two incidents within one day established the rule. An aggregator gave the Gnaoua festival as 24–26 June 2027; the organiser's own site said 25–27 June 2026 — the aggregator was simply wrong. The Marrakech Marathon was the inverse: an aggregator claimed 31 January 2027 and was dismissed because the official site still showed 25 January 2026 — then hours later the official site rolled over to exactly what the aggregator had said.

The rule is not that aggregators lie. It is that only the organiser's page is authoritative at the moment you read it, and entries go stale on their own.

Editorial standards

  • Honest counterweights. Event pages carry considerations alongside highlights — what is genuinely harder, more crowded or more uncertain. A page listing only upsides reads like an OTA listing and is worth nothing to someone deciding.
  • Primary sources. The Tibherine crash article publishes eight deaths, from the Bureau of Aircraft Accidents Archives, where several travel sites say four.
  • Scope honesty. That article states plainly that no standard itinerary visits the wreck, rather than implying a stop the tour does not include.
  • SERP budgets. Meta descriptions are bounded at both ends — 85 to 165 characters — because fixing over-long ones by truncating produced 43-character fragments that wasted the slot.

The six-locale publishing recipe

Content migrations are Python scripts run as PYTHONIOENCODING=utf-8 py <file>, written to disk rather than passed as heredocs — backslashes and French apostrophes are consumed by the shell otherwise. Each script asserts its anchors match exactly once before writing, so a changed file fails loudly instead of silently patching the wrong place.

09Performance and platform

Rendering strategy

1,052 pages are prerendered as static HTML at build time. Tour and blog detail pages use generateStaticParams across all six locales; only the contact and newsletter endpoints are dynamic.

These are origin-level CrUX figures. Individual pages lack sufficient field samples, so CrUX falls back to origin aggregates — which means the site is unassessable rather than failing.

Platform-level guards

  • CSP is asserted by test, after undefined CSS custom properties invalidated whole declarations and elements inherited an ancestor's colour.
  • Motion imports are checked: the motion component cannot tree-shake below 34 kB, so m + LazyMotion is enforced.
  • LCP guards assert the hero image is prioritised.
  • Rate limiting and origin checks protect the two API routes.

A proxy defect with real SEO cost

Next.js middleware matchers exclude paths containing a file extension by default. That meant robots.txt and sitemap.xml bypassed the proxy entirely — and the Vercel preview domain wild-atlas-six.vercel.app was being indexed by Google as a separate site, competing with the production domain.

Fixed by adding both files to the matcher explicitly and returning early for host-level files, with a test asserting the matcher still covers them.

Assessment

The engineering is in unusually good order for a project this size. The test culture is the strongest asset — not because 402 assertions is a large number, but because each one encodes a defect that actually escaped to production, which makes the suite a record of how this system fails rather than a checklist.

The technical SEO is close to exhausted as a lever. Structured data, hreflang, sitemaps, internal linking and indexing are all correct and verified. What remains is not a code problem: commercial queries sit near position 52 because the domain lacks external authority, and that is earned through backlinks and a Business Profile rather than shipped from a repository.

The most valuable remaining engineering task is small: adding image support to the markdown renderer. The project owns 165 photographs from real departures and cannot currently place any of them inside an article.
